# Game pictures

Every illustrated picture file shipped with SogoTable. Source spec: `docs/pictures-spec.md` (from SogoAI, sibling of
`docs/sfx-spec.md`).

## Decision (AREC, 2026-11-12)

- **Abstract:** ship small illustrated picture files where the procedural SVG art is weakest: Last Orders portraits,
  cards, drinks, card backs and table, and the Chinese Checkers board.
- **ReExplain:** pictures are browser presentation only. They are made once, offline, on SogoAI's model manager, and
  committed as WebP. Phones never call the AI PC and nothing is drawn during a game. Each game's `assets.js` maps a
  slot id to its file; an id with no file keeps its SVG.
- **Evaluate:** industry standard (pre-made, compressed, cached art). Risks are download weight and a mapped file that
  is missing (`imageSvg` can't detect a 404, so it would draw blank). Weight is held down by sizing to the largest
  on-screen use × 3 for phone screens, WebP quality 75-78, and the service worker's runtime cache (a picture downloads
  only when a card using it is seen). `workers/tests/game-pictures.test.js` fails if a mapped file is missing or over
  its size budget.
- **Conclude:** adopt. **Picture files allowed; the SVG art stays the fallback** for every slot, and stays the only art
  for Chinese Checkers marbles, Realmwright meeples and tiles, and Battleship ships (they need transparency or exact
  edge layouts the model can't promise). New slots in other games need a placement decision first
  (`docs/module-ownership.md`), with the same null-fallback pattern.

## Differences from the spec (and why)

- **Scope:** every Last Orders pack (12 characters, 182 cards, 30 drinks), not only base. MojoSOGO asked for all of
  the Last Orders graphics on 2026-11-12.
- **Card and drink art, portraits: 384x384, not 512.** The largest on-screen use is a 124 px card face, so 384 px
  covers a 3× phone screen. All 227 Last Orders files come to 3.9 MB (13-25 KB each), close to the spec's 3 MB per game even with every pack.
- **Card backs: 512x716 (5:7), not square.** The game shows backs on a 100×140 card, and a square picture would be
  cropped at the sides.
- **One seed per card and drink,** three seeds for portraits, backs, table and board. Three for every card would triple
  a two-hour GPU run; weak cards were re-rolled instead. Each card prompt is a hand-written action scene for that card
  (the card name alone drew the character standing still); cards that are an object (spikes, chasers) are drawn as a
  still life with no people. Hrolga still comes out bearded on most of her cards (beardless in her portrait); a known
  dwarf trope, left as is.
- **Portraits use qwen-image21,** not wai-illustrious, to keep one look across the whole game.

Best practice: serve images at displayed size × device pixel ratio (web.dev, https://web.dev/learn/performance/image-performance).

## Style

One style for every game, appended to every prompt (shown as `+ STYLE` below):

> realistic graphic novel illustration, fine detailed ink linework with delicate cross-hatching, soft muted
> naturalistic coloring like watercolor and marker, realistic anatomy and expressive faces, clean simple background,
> high detail

Card and drink prompts also ask for "no text, no letters, no border": the game draws the frame and the words.

## How files are made

1. On SogoAI only (loopback): `POST http://127.0.0.1:8793/generate?format=png` with
   `{ "owner": "sogotable", "priority": "maintenance", "model": "qwen-image21", "prompt", "width", "height", "seed" }`.
   A 409 means the PC is busy: wait 5 minutes and retry. Masters also land in `C:\AI\ComfyUI\output\sogoai\sogotable\`.
2. Scale with Pillow (ComfyUI's Python) to the size in the table, save WebP quality 78 (75 for 1024 px files), `method=6`.
3. Save as `static/games/<game>/img/<slot-id>.webp` with ":" turned into "-", and add the id to that game's
   `assets.js` list. Only list ids whose file is committed (the test checks).
4. Add a row below. Keep the PNG masters out of git.
